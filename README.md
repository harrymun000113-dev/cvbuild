# 커리어노트 · 취업 자기소개서 MVP

한국어로 직무를 분석하고 경험을 자기소개서로 재구성하는 **로컬 실행용 Streamlit 웹앱**입니다. 사용자가 자신의 OpenAI API 키를 입력합니다. 관리자 키·DB·회원가입 없이 실행합니다. Next.js보다 설치와 수정이 간단한 Python 단일 앱을 선택했습니다.

## 새 기능: 작성 후 검사 · 피드백

상단 **작성 후 검사 · 피드백** 탭에서 완성한 자소서를 붙여 넣고 **피드백 분석**을 누르세요. 기존 자소서나 현재 편집 결과를 가져올 수도 있습니다. 입력 중 자동 API 요청은 없으며, 버튼을 누를 때만 유료 검사를 실행합니다.

- 총평, 잘된 점, 우선 개선점, 명확성·구체성·구조·자연스러움 각 25점의 글쓰기 참고 점수를 제공합니다. 실제 채용 점수가 아닙니다.
- **AI 문체 문장 비율** = AI처럼 느껴지는 상투적 문체로 표시한 문장 수 ÷ 전체 검토 단위 수 × 100. 실제 AI 작성 확률, 탐지 정확도, 표절률이 아닙니다. 사람이 쓴 글도 표시될 수 있고 AI가 쓴 글이 표시되지 않을 수 있습니다.
- 문장 하이라이트: 노랑은 AI 문체, 분홍은 어색한 표현, 보라는 두 항목 모두입니다. 마우스 툴팁과 문장별 상세 영역에서 판단 이유·수정 제안을 확인할 수 있습니다.
- 수정 제안은 직접 확인하고 반영합니다. 원문을 자동으로 바꾸지 않습니다. 원문 또는 직무·기업·문항을 바꾸면 이전 점수와 하이라이트를 숨기고 재검사를 안내합니다.
- 최대 4,000자 / 40개 문장·소제목, 출력 최대 7,000토큰. 문장 경계는 문장부호와 줄바꿈에 기반하므로 약어·목록·소제목은 별도 검토 단위가 될 수 있습니다.
- 생성과 검사 합계 20회, 세션 예산·연속 요청 제한을 공유합니다. 보고서를 Markdown으로 다운로드할 수 있습니다.
- 추가 파일: `feedback.py`(응답 스키마·문장 위치·안전한 하이라이트), `feedback_ui.py`(피드백 위젯), `prompts/feedback.md`(별도 피드백 프롬프트), `tests/test_feedback.py`.
- Responses API의 엄격한 JSON Schema 응답을 검증합니다. 누락·중복·순서 오류나 미완료 결과는 점수를 표시하지 않습니다. HTML 출력에 넣는 원문·이유는 모두 이스케이프합니다.

## 1. 빠른 실행

Python 3.11 이상을 설치하세요. 검증 환경은 Python 3.14 / Windows입니다. 압축을 풀고 **career-ai 폴더 안에서** 터미널을 여세요.

### Windows PowerShell

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
```

가상환경 활성화가 필요 없어 PowerShell 실행 정책을 바꿀 필요도 없습니다. 설치 후에는 마지막 명령만 실행하세요. 또는 `run.bat`을 더블클릭하면 최초 설치와 실행을 처리합니다. 중지는 터미널에서 Ctrl+C입니다.

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

브라우저에서 http://127.0.0.1:8501 을 엽니다. 포트가 사용 중이면 실행 명령 끝에 `--server.port 8502`를 붙이세요. 설치 시 인터넷 연결이 필요합니다.

## 2. 사용 순서

1. OpenAI Platform에서 발급한 API 키를 왼쪽에 입력합니다. ChatGPT 구독과 API 결제는 별개입니다.
2. 선택 사항인 **연결 확인**은 모델 조회로 인증/모델 접근을 확인하며 텍스트 생성 요청을 하지 않습니다. Responses 생성 권한·잔액은 첫 생성에서 최종 확인합니다. 모델 조회 권한이 없는 제한 키는 조회 실패 후에도 생성은 시도할 수 있습니다.
3. 기능 카드를 선택하고 직무, 기업, 문항, 분량, 경험을 입력합니다. STAR 입력과 자유 경험, 기존 자기소개서를 모두 지원합니다.
4. 기업 분석은 **기업 자료** 탭에 공식 자료 본문과 출처명·날짜·URL을 붙여 넣어야 합니다. 웹 검색이나 URL 본문 자동 수집은 하지 않습니다.
5. 전송·비용 안내에 동의하고 생성합니다. 편집한 결과를 복사하거나 `.txt` / `.md`로 다운로드합니다.
6. **현재 입력으로 재생성**은 유료 신규 요청입니다. 이전 결과가 새 결과로 대체되므로 필요한 결과는 먼저 다운로드하세요. 실패하면 기존 결과를 유지합니다.
7. 기능별 마지막 결과를 따로 유지합니다. 입력 변경 후 기존 결과에는 변경 안내가 표시됩니다. 전체 초기화는 입력, 키, 결과를 지우되 예산 카운터는 유지합니다.

## 3. 기능과 원문 템플릿

사용자가 참조 대화에서 제공한 10개 템플릿을 각각 Markdown 파일로 옮겼습니다. 전송 과정의 HTML 공백·줄바꿈 이스케이프와 인용 토큰만 정리했습니다. 원문에 있는 역할·수행 기준·출력 구조를 사용합니다.

| 기능 | 파일 | 핵심 출력 |
|---|---|---|
| KSA 기반 역량평가 | `prompts/ksa-evaluation.md` | 직접·간접·예상 밖 경험, KSA, 활용 문장 |
| 직무 KSA 분석 | `prompts/job-ksa.md` | K/S/A별 2~3개 역량, 적용 사례, 개발법 |
| 경험 → 직무 강점 | `prompts/career-strength.md` | 역할, KPI 3개 이내, STAR 표현 |
| 기업 특성 분석 | `prompts/company-analysis.md` | 경쟁력 3가지, 근거, 경쟁사 차별성 |
| OKR · 입사 후 포부 | `prompts/okr.md` | 목표 3개, 목표별 KR 2~3개 |
| 성장과정 | `prompts/growth-story.md` | 소제목 + 가치관 중심 본문 |
| 성격의 장단점 | `prompts/personality.md` | 소제목 + 강점·약점·보완 행동 |
| 직무수행 경험 | `prompts/job-experience.md` | 소제목 + 경험·의미·역량·직무 |
| 지원동기 및 입사 후 포부 | `prompts/motivation.md` | 소제목 + 계기·기업 연결·실행 목표 |
| 맥킨지 7STEP | `prompts/mckinsey-7step.md` | 문제 정의→구조화→우선순위→계획→분석→종합→실행 |

`prompts/system.md`에는 사실성 규칙을 추가했습니다. 원문 템플릿의 사례 요구보다 본인 경험의 사실성을 우선하며, 자료가 없는 수치나 경쟁사 비교는 만들지 않도록 지시합니다. 7STEP의 60:40 메모는 사용자 제공 휴리스틱으로 취급합니다.

## 4. 폴더 구조 / 설계

```text
career-ai/
├── app.py                  # 한국어 UI, 세션 상태, 생성·편집·다운로드
├── core.py                 # 기능 목록, 입력 검증, 프롬프트 조립, 예산
├── service.py              # 요청별 OpenAI 클라이언트, 오류 메시지
├── prompts/
│   ├── system.md           # 모든 기능에 적용할 공통 규칙
│   └── ... 10개 기능.md    # 사용자 원문 프롬프트
├── tests/
│   ├── test_core.py        # 유효성·예산·문자 수
│   ├── test_service.py     # 실제 SDK + 가짜 HTTP 응답
│   └── test_app.py         # Streamlit 화면 흐름
├── .streamlit/config.toml  # 로컬 바인딩, 테마, 통계 비활성화
├── requirements.txt        # 검증한 직접 의존성 버전
├── run.bat                 # Windows 설치·실행 도우미
└── README.md
```

```text
브라우저 입력 → 세션 메모리 → 입력 검증 → 공통 규칙 + 기능 템플릿
                                         + 사용자 JSON
                           → OpenAI Responses API → 결과 편집 → 다운로드
```

키는 프롬프트 조립 함수에 전달하지 않고 인증용으로만 사용합니다. `OpenAI(...).responses.create(model=..., instructions=..., input=..., max_output_tokens=..., store=False)`와 `response.output_text`, `response.usage`를 사용합니다. 클라이언트를 요청마다 만들고 닫습니다. 대화 기록을 자동으로 다음 요청에 붙이지 않아 이전 결과 때문에 토큰이 누적되지 않습니다.

### 템플릿 수정

해당 `prompts/*.md`만 편집하면 다음 생성부터 반영됩니다. 코드 내부의 `str.format`으로 원문 전체를 해석하지 않으므로 중괄호를 자유롭게 사용할 수 있습니다. 입력값은 별도 JSON 사용자 메시지로 전달하여 원문의 자리표시자를 대체하도록 지시합니다. 기능을 추가하려면 `core.py`의 FEATURES와 검증 조건을 함께 추가하세요.

## 5. 비용·분량 제어

- 기본 모델: `gpt-4.1-mini`. 비추론 모델로 응답 분량 예측이 단순하며 텍스트 MVP에 사용합니다. '최신 모델'이라는 의미는 아닙니다. 최신 설치 SDK 방식을 사용합니다.
- 전체 입력 최대 12,000자, 항목별 상한, 자소서 목표 200~3,000자.
- 분석 출력 최대 4,500토큰, 자소서 1,800~6,000토큰.
- 세션 생성 최대 20회, 요청 간 5초, 기본 세션 예산 $0.50 (설정 범위 $0.05~$2).
- SDK 자동 재시도 0회, 응답 읽기 타임아웃 60초 / 연결 10초. 총 실행 시간의 엄격한 상한은 아닙니다.
- UTF-8 바이트 수와 출력 상한으로 보수적으로 비용을 예약한 뒤 usage로 정산합니다. 실패·타임아웃·usage 미제공은 예약 금액을 유지합니다.
- 표시 단가: 2026-09-16 확인 기준 입력 $0.40 / 출력 $1.60 (100만 토큰당). 캐시 할인은 계산하지 않습니다. 모델·단가 변경 시 `core.py`를 함께 갱신하세요. 표시액은 실제 청구액을 보장하지 않습니다.
- 앱 재접속·다른 탭은 별도 세션입니다. 예산은 계정 전체의 강제 청구 한도가 아닙니다. 공용 서비스에는 사용자 인증과 공유된 사용량 제어가 추가로 필요합니다.
- 글자 수는 Python Unicode 코드 포인트 기준입니다. 소제목도 포함합니다. 분석 기능은 글자 수를 참고 분량으로 취급합니다. 자소서가 상한을 넘으면 경고하고 직접 편집할 수 있습니다. 자동 절단이나 자동 유료 재생성은 하지 않습니다. 채용 사이트의 바이트/문자 계산 방식은 다를 수 있습니다.

## 6. API 키 및 보안

**'서버에 저장하지 않음'은 영구 저장하지 않는다는 뜻입니다.** Streamlit 구조상 키는 브라우저에서 Python 서버로 전달되어 위젯 세션 메모리에 존재합니다. 서버로 키를 전혀 보내지 않는 구조는 아닙니다. 이 프로젝트는 기본적으로 내 PC의 127.0.0.1에서만 접속합니다.

- `.env`를 사용하지 않는 이유: 사용자별 키를 입력받는 앱이므로 공유 서버 키를 파일에 둘 필요가 없습니다. 환경변수 API 키로 대체하는 옵션도 의도적으로 제공하지 않습니다.
- DB, 파일, 브라우저 localStorage, Streamlit 캐시, 자체 로그에 키·입력·결과를 저장하지 않습니다. 키와 자료는 활성 세션 메모리에 존재하며 **키 지우기 / 전체 초기화**로 앱 참조를 제거할 수 있습니다. Python 메모리의 물리적 즉시 소거까지 보장하지는 않습니다. 브라우저 종료만으로 즉각적인 서버 메모리 삭제를 보장하지 않습니다.
- 오류 원문·트레이스백을 UI에 내보내지 않습니다. SDK 원시 오류 대신 고정된 한국어 메시지를 사용합니다. `OPENAI_LOG` 같은 디버깅 로깅, 트래픽 기록, 세션 기록 기능은 켜지 마세요.
- API 호스트는 `https://api.openai.com/v1`로 고정합니다. 환경 프록시 사용을 끕니다. 기업 프록시가 필요한 환경은 신뢰할 수 있는 관리자와 HTTP 클라이언트 설정을 별도로 검토하세요.
- `store=False`는 Responses 응답 상태 저장을 끄는 옵션이며 OpenAI의 모든 로그 보존을 없애는 것은 아닙니다. OpenAI 데이터 정책은 별도로 적용됩니다.
- 연락처, 주민번호, 고객명 등 민감한 내용을 지우고 입력하세요. 키로 보이는 문자열은 본문 검증에서 차단하지만 모든 비밀을 탐지하는 보안 솔루션은 아닙니다.
- 생성 결과는 일반 텍스트/코드 상자로 표시합니다. 피드백 원문은 HTML 이스케이프 후 앱이 정한 색상만 적용합니다. 모델의 HTML, 링크, 이미지를 실행하거나 자동 로딩하지 않습니다. 사실성 지시는 오답을 완전히 막지는 못합니다.
- 외부 공개 배포는 이 MVP 범위에 포함하지 않았습니다. 공개 시 HTTPS, 접근 제어, 프록시/호스팅 로그의 본문·인증 헤더 마스킹, 사용자 동의, 세션 수명 관리, 계정별 속도 제한을 추가하세요. 기본 CORS/XSRF 보호를 끄지 마세요.
- 다운로드한 파일과 클립보드는 사용자가 관리합니다. 앱의 초기화가 이미 내려받은 파일을 삭제하지는 않습니다.

## 7. 검증

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```

테스트는 가짜 인증값과 모의 응답만 사용하므로 과금하지 않습니다. 검증 범위는 입력 경계, 키가 프롬프트에 섞이지 않는 구조, 예산 예약/정산, SDK 요청 형식, store=False, 오류 분류, 미완료 응답, 화면 전환과 결과 편집입니다. 실제 OpenAI 유료 생성 품질·계정 인증은 사용자의 키 입력 후 확인해야 합니다.
